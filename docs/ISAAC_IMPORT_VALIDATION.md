# Isaac Sim URDF import validation — 2026-10-26

The latest stable targets checked on this date are Autodesk Fusion
**v.2706.14**, released October 20, and **Isaac Sim 6.2.0 GA**, announced
October 22. These are production releases, not preview or nightly builds.
Sources: [Autodesk release notes](https://help.autodesk.com/cloudhelp/ENU/Fusion-ReleaseNotes/files/FIC-REL-NOTES-INC.htm),
[NVIDIA GA announcement](https://forums.developer.nvidia.com/t/isaac-sim-6-2-general-availability/386512),
and [Isaac Sim release notes](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/overview/release_notes.html).

The executed target was NVIDIA's **`isaacsim-asset-isolated==6.2.0.0`**,
which contains the actual 6.2 URDF importer and asset transformer without
starting Omniverse Kit. NVIDIA publishes its
[package](https://pypi.org/project/isaacsim-asset-isolated/6.2.0.0/) and
[versioned package definition](https://github.com/isaac-sim/IsaacSim/blob/v6.2.0/python_packages-isolated.toml).
Its pinned backend is `urdf-usd-converter==0.3.2`, with
`usd-exchange==2.3.0`, `usd-optimize==1.1.0`, and
`isaacsim-robot-schema==6.2.0.0`. The complete tested dependency lock is
[`scripts/requirements-isaac-import.txt`](../scripts/requirements-isaac-import.txt).

Validation ran on Ubuntu 24.04/aarch64, Python 3.12.3, with NVIDIA GB10 hardware
and driver 580.178.04. No full Isaac Sim installation, paid service, license
acceptance environment variable, or GUI was used.

## Executed checks

The class and legacy fixtures in
[`tests/fixtures/isaac_urdf`](../tests/fixtures/isaac_urdf/) were generated by
the real `Link`, `Joint`, class `URDF.write_file`, and legacy `write_urdf`
implementations from `main@58088c6` plus PR #19 at `d513ff4`. Fusion API objects
were numerical doubles, and the STL cubes are synthetic. Thus this tests the
exporters' actual naming, frame arithmetic, and decimal serialization followed
by the real target importer; it is not a live Fusion CAD export.

The three-link fixture includes a root rotated +90 degrees about X and
translated by (0.1, 0.2, 0.3) m, two geometric fixed joints, and two instances
named `Arm link:1` and `Arm link:2`. Their output names and filenames are
`Arm_link_1` and `Arm_link_2`. The root deliberately has mass `0.000000001` kg
and principal inertias near `0.000000000000066666667` kg m², so blanket rounding
to six decimal places would erase them.

| Input | Links | Source joints | Imported mesh prims | Imported collision prims | Result |
| --- | ---: | ---: | ---: | ---: | --- |
| Class URDF writer | 3 | 2 | 6 | 3 | PASS |
| Legacy URDF writer | 3 | 2 | 6 | 3 | PASS |
| Class output after native CoACD | 3 | 2 | 6 | 3 | PASS |
| Legacy output after native CoACD | 3 | 2 | 6 | 3 | PASS |
| Concave L-prism after native CoACD | 1 | 0 | 3 | 2 | PASS |

The L-prism came from the collision pipeline's native test shape. Native CoACD
produced **two** convex collision pieces on one link. Both named collision
pieces survived as separate USD `CollisionAPI` prims. All runs preserved source
joint names, link identities, masses, centers of mass, and principal inertia
magnitudes within the smoke test's float32 tolerance. No USD dependency was
unresolved. The tiny root mass became `9.999999717180685e-10` kg and its three
principal inertias became `6.666667001428705e-14` kg m², remaining positive.

A scientific-notation control copy also passed the 6.2 importer. The older
Omniverse scientific-notation warning in PR #11 was therefore not reproduced
in this target. The precision-preserving decimal output remains accepted;
six-place rounding is unnecessary and loses valid small quantities.

## Repeating the asset import

Use a dedicated Python 3.12 environment. The tested isolated dependency set
downloads roughly 400 MB, predominantly the USD optimizer, rather than the
full Isaac Sim/Kit application.

```bash
python3.12 -m venv work/isaac-import-env
work/isaac-import-env/bin/python -m pip install -r scripts/requirements-isaac-import.txt
work/isaac-import-env/bin/python scripts/smoke_test_isaac_urdf.py \
  tests/fixtures/isaac_urdf/class.urdf work/isaac-class --require-decimal
work/isaac-import-env/bin/python scripts/smoke_test_isaac_urdf.py \
  tests/fixtures/isaac_urdf/legacy.urdf work/isaac-legacy --require-decimal
```

Each output directory must be new. The runner emits a JSON report and returns
nonzero on failed checks. It resolves local mesh/texture files, rejects missing
assets and non-finite numbers, checks imported named collisions, and inspects
the composed USD including instance proxies. For structured 6.2 assets it
selects the `Physics=physics` variant in the session layer before checking
inertials and collisions; the saved USD remains untouched.

With the optional collision dependencies installed, repeat the multi-piece
check with:

```bash
python scripts/convexify_urdf.py tests/fixtures/isaac_urdf/concave/robot.urdf work/concave-collision
work/isaac-import-env/bin/python scripts/smoke_test_isaac_urdf.py \
  work/concave-collision/robot.urdf work/isaac-concave --require-decimal
```

The source concave fixture contains one collision; the decomposed URDF and its
USD report should each contain two. The collision report records backend
settings, hashes, versions, and piece geometry.

The runner uses the
[current `URDFImporter`/`URDFImporterConfig` API](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/py/source/extensions/isaacsim.asset.importer.urdf/docs/index.html).
`URDFParseAndImportFile` was removed in 6.0, as documented in the
[migration guide](https://docs.isaacsim.omniverse.nvidia.com/6.2.0/migration_guides/isaac_sim_6_0/urdf_mjcf_importer_exporter_pipeline.html).
In a separately installed full Isaac Sim environment, `--kit` starts headless
`SimulationApp`; that optional branch has not been executed here and does not
accept a license on the user's behalf.

## Limits

These results establish acceptance of the tested decimal values, underscore
filenames, repeated link identities, and multi-piece collision assets in the
latest stable asset importer. No physics engine was stepped. Contact
stability, joint drives, full inertia-axis orientation, sensor rendering, live
Fusion build behavior, and arbitrary complex assemblies require their own
fixtures and runtime validation. The smoke runner intentionally requires
explicit inertials, local assets, and names that survive USD conversion; it
does not configure ROS package resolution or infer missing physical data.
